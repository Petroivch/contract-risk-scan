# Local-First Data Architecture (Mobile)

## 1. Архитектурный принцип
- Кодовая база сохраняет локальный transport-режим mobile-клиента как отдельный сценарий, но текущий runtime по умолчанию идет через backend-first HTTP path.
- Пользователь устанавливает только релизную сборку.
- Серверная синхронизация и backend persistence остаются отдельным режимом, а не скрытой частью device-only copy.

## 2. Что реально локально в текущем mobile runtime
1. Пользовательские настройки:
- языковое предпочтение в AsyncStorage.

2. Runtime-состояние сессии:
- выбранная роль, промежуточные статусы и результат текущего анализа держатся в памяти процесса.

3. Временные файлы:
- системный picker или текущий runtime могут оставить временную копию документа на время чтения;
- собственный app-managed file cache сейчас не создается.

## 3. Что серверно-опционально
1. `core-api` runtime state для upload/status/report и любая будущая persistence-слойка, если она будет добавлена отдельно.
2. Резервная копия и кросс-девайс синхронизация.
3. Централизованный аудит.
4. Расширенная аналитика при наличии сети.

## 4. Политики без хардкода
- Лимиты и политики задаются через `app_config`, не через magic numbers в коде.
- Ключи:
  - `mobile.cache.max_contracts`
  - `data.retention.contract_hard_delete_days`
  - `data.retention.audit_logs_days`
  - `language.default`, `language.supported`
  - `locale.default`, `timezone.default`

## 5. Ограничения для будущего device storage
1. Additive-first изменения.
2. Минимум тяжелых rewrite-операций.
3. Любые SQLite/file-cache миграции актуальны только если соответствующие feature flags будут включены.

## 6. Критерии приемки
1. Текущий основной flow работает: роль -> загрузка -> backend analysis -> отчет; отдельный local transport не должен документироваться как уже активный по умолчанию, если runtime собран с `API_TRANSPORT=http`.
2. Язык и локаль консистентны в API и БД.
3. Никакого хардкода лимитов и enum в мобильном коде.
4. Нельзя документировать несуществующий persisted history/cache как уже включенную часть runtime.
